# PDF inspection development scope

The scanner uses lopdf 0.47.0 (MIT, default features disabled) with strict parsing and a zero-byte load-time stream decompression allowance. This deliberately rejects compressed object and cross-reference structures rather than allowing per-stream load limits to multiply into unbounded aggregate expansion. The parser remains synchronous and builds an in-memory object graph: use the supervised worker for hard memory and wall-clock limits. Cooperative deadline checks before/after parsing cannot interrupt a parser call.

Identified indirect stream objects, including `/Type /EmbeddedFile`, are scanned recursively. The current filter allowlist is no filter or one `FlateDecode`; decode parameters, external stream files, other filters, and encrypted documents are unsupported. Each decoded stream shares attachment count, recursion, per-object size and aggregate extraction budgets. Object-number labels are used instead of private stream text. Stream decoding failure and parser rejection are UNSCANNED, not CLEAN. Resource tracker failures remain ERROR. Existing detected-content precedence is retained, including PDF/ZIP polyglots.

This does not render, sanitise or rewrite documents. It does not extract text, resolve arbitrary external references, implement PDF JavaScript behavior, or comprehensively inspect historical incremental revisions. It scans loaded indirect streams, not every possible PDF encoding. Malformed structure is reported as an inspection limitation, not as confirmed malware or a new SUSPICIOUS verdict. A distinct structural suspicion interface remains future work. Purely in-memory parser allocations and CPU behavior rely on worker process limits; no memory benchmark is claimed.

Selection evidence: lopdf's maintained API offers strict loading, load-time decompression limits and capped stream decompression. Other libraries were not benchmarked in this checkpoint. See https://docs.rs/lopdf/0.47.0/lopdf/struct.LoadOptions.html and https://docs.rs/lopdf/0.47.0/lopdf/struct.Stream.html . The upstream changelog documents why decompression limits matter: https://github.com/J-F-Liu/lopdf/blob/main/CHANGELOG.md .
