Implemented strict structural PDF loading with lopdf 0.47.0, default features disabled; scans loaded indirect streams including EmbeddedFile streams. Recursive scanning uses the existing detection engine, preserving signature and RSIDB matching. Supported filters: unfiltered or one FlateDecode, without DecodeParms. Parsing and decoding failures are UNSCANNED. Tracker resource failures remain ERROR. Existing detection precedence remains unchanged. The PDF input is not rendered, sanitised or rewritten.

Tests generate clean and actual EICAR stream objects, including forced FlateDecode compression, embedded-file streams, malformed/truncated PDF and extraction-budget limits. Clean supported fixtures return CLEAN, EICAR returns DETECTED, malformed/truncated structure returns UNSCANNED, and over-budget content does not return CLEAN. These are deterministic small fixtures, not a broad false-positive or memory benchmark. The corpus does not independently prove every embedded-file referencing arrangement or unsupported filter combination.

Limits: streams share attachment count, per-object extracted size, aggregate extraction bytes and recursion limits. Decoder output is capped. Load-time decompression allowance is zero, deliberately declining compressed object/xref structures rather than multiplying per-stream load budgets. Before/after parser and per-object deadline checks are cooperative; the synchronous parser cannot be interrupted by them. Use the existing supervised worker for hard memory and deadline limits. No peak RSS measurement was performed. Parser object graphs can consume memory up to worker limits.

Unsupported: encrypted PDFs; other filters, filter chains, DecodeParms/predictors, external streams; load-time compressed structures; comprehensive inspection of incremental history, arbitrary PDF encodings and JavaScript semantics. No new SUSPICIOUS enum or structural suspicion classifier was added: malformed structures are explicit inspection limitations, not confirmed malware. Existing ERROR/TIMEOUT compatibility remains unchanged. Embedded streams are labelled by object number, without exposing private stream text.

Selection and limitations are documented in docs/PDF_INSPECTION_PHASE3C2.md.
