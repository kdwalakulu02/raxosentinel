4. UNSUPPORTED SIGNATURE TYPES IN CLAMAV

In addition to whole-file hash signatures, official ClamAV CVDs distribute complex
signature types unsupported by our hash engine:
  - PE section hashes (.mdb, .msb) : 2,670,550 signatures
  - Byte patterns (.ndb, .ndu)     :   106,069 signatures
  - Logical signatures (.ldb, .ldu):   322,446 signatures
  - Total unsupported signatures   : 3,099,065 signatures

Why They Were Rejected:
  1. PE Section Hashes (.mdb, .msb): Require parsing PE32/PE32+ executable container
     headers and section tables, extracting virtual section boundaries, and hashing
     only virtual sections. Applying whole-file hashing to section hashes would create
     false negatives.
  2. Byte Patterns (.ndb, .ndu): Sub-string pattern sequences containing hex wildcards,
     regex jumps, and anchoring constraints rather than cryptographic file digests.
  3. Logical Signatures (.ldb, .ldu): Multi-condition Boolean expressions combining
     byte patterns, container metadata, and target file type constraints.

Requirements to Safely Support in Future Milestones:
  - PE Section Scanning: Integrate a safe, bounded PE parsing module (zero unsafe code,
    strict bounds checking on SectionHeaders, DOS/NT header offsets, and section data ranges)
    within the supervised worker under existing Landlock/rlimit sandboxing.
  - Pattern Automaton: Expand `SignatureDatabase` pattern automaton (already using
    Aho-Corasick) to ingest fixed byte patterns with pre-filter verification.
  - Logical Engine: Implement a strictly bounded AST evaluator for Boolean operations
    with recursion depth limits to prevent stack overflow or DoS on hostile inputs.
