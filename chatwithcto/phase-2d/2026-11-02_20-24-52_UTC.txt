1. Status

The production source adapter is MalwareBazaar; synthetic source adapters A and B are compiled only in unit tests and are explicitly classified synthetic test only. 2. Registry format
Each new generation contains database.rsidb, registry.json, associations.json, and one source-<source-id>.json evidence file per source. The version-1 registry holds stable source IDs, name, provider, acquisition method and Unix timestamp, classification, provenance qualification, redistribution status, enabled state, accepted-indicator count and evidence SHA-256. Registry and association filenames and SHA-256 digests are embedded in the RSIDB provenance manifest. Source descriptors are fixed by supported code adapters, not created by arbitrary operator labels. The existing MalwareBazaar source status means locally consistent evidence, not a provider-issued signature. Test adapters are test-only and cannot be used by production binaries.

3. Source associations and scanner records
Version-1 associations store each unique SHA-256 with sorted source-ID, size and source-specific family claims, plus a quarantine flag. Source evidence is independently parsed and associations are deterministically re-derived at every generation load; the persisted associations must match exactly. For a non-conflicting SHA-256 the scanner database contains one SHA-256/size operational record with a generic intelligence detection name, independent of source count. Family labels remain source-specific in associations. If any sources disagree about size, that entire SHA-256 is quarantined and omitted from operational scanner records; no size is silently selected. Lookup performs no source-table work. JSON tables are bounded and intended for this core, not claimed to be a compact binary representation.

6. Security, publication and compatibility
Strict loading validates RSIDB structure and payload, manifest, registry and association digests, each evidence file, supported source descriptors, re-derived associations and correspondence to the exact owned operational index. Tests reject invalid source IDs, missing evidence, and a forged source association even after the association digest and internal RSIDB checksum are recomputed. Locally consistent evidence and source labels do not independently authenticate upstream acquisition, establish malware classification, or grant redistribution permission. Private research handling remains mandatory.

The new publisher uses the Phase 2D.2 owner-controlled private root and descriptor-relative, no-follow operations, writes and syncs every file, validates the staged generation, syncs its directory, performs a same-filesystem no-replace directory rename, then syncs the root. Published generations are not modified. Pre-publication failures attempt confined cleanup; ambiguous staging leftovers remain subject to the Phase 2D.2 recovery limitations. Post-rename root-sync failure reports uncertain durability. No new fault-injection or real power-loss test was added for the new multi-file publication routine.

Legacy Phase 2D.2 single-source generation loading remains supported; an executable test loads and migrates a prior-format fixture. The preserved genuine 100-record Phase 2D.2 generation was migrated to a NEW private generation phase2d3-core in /home/vscode/raxosentinel-private-phase2d1 and successfully loaded by the release scanner against a benign file. Its original pair and prior generation remain untouched. No API call or malware binary download occurred.

11. Remaining limitations
Only MalwareBazaar is usable as a real-source adapter. The synthetic adapters are restricted to unit tests; a second independent real feed requires a separately reviewed adapter and evidence-validation policy. Local integrity digests do not provide provider-issued signatures. Current source inspection CLI commands do not inspect multi-source generations; the validated Rust API does. Merging two generations with the same source ID fails rather than choosing a refresh; select one generation for that source. No broad scale/performance study, multi-source publication fault-injection campaign, or real power-loss durability proof was performed. Owner/root compromise remains outside the supported threat model.
