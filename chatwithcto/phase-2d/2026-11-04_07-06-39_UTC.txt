## 1. Rollback Consistency Defect: Investigation, Root Cause & Architectural Fix

### 1.1 Was a Rollback Consistency Defect Actually Found?
**YES.** A critical architectural defect existed in the rollback and status persistence subsystem prior to Phase 2D.7C.

### 1.2 Defect Manifestation
When an update was applied and subsequently rolled back:
1. `raxosentinel db rollback` pointed the `current` filesystem pointer back to `phase2d6-unified` (542,057 indicators).
2. However, `update_status.json` on disk still contained the provider metadata from the revoked generation (`phase2d7-unified-...`), claiming ClamAV was at version `main:63,daily:28174` with 541,954 indicators and that the last summary had 542,058 indicators.
3. When the operator or scheduler executed `raxosentinel db update --status`, the output displayed a severe contradiction:
   - `Current RSIDB Generation : phase2d6-unified`
   - `ClamAV Source Version    : main:63,daily:28174` (Contradicting the active database, which actually contained 28173!)
4. When `raxosentinel db update --check` or `--apply` was invoked after rollback:
   - The engine inspected `status.sources["clamav"].source_version` (which was stale at `28174`).
   - If the upstream provider was at version `28174`, `check_update()` concluded:
     `"ClamAV CVD distribution unchanged at version main:63,daily:28174 (available=false)"`.
   - The updater **refused to re-apply the update**, falsely believing the system was already up-to-date, even though the active database had been rolled back to `28173`!
   - This completely broke Scenario B ("Reapply after rollback").

### 1.3 Root Cause Analysis
1. **Flawed `engine.rs:rollback()` Logic**:
   The existing `rollback()` implementation only updated `status.current_generation` and `status.previous_generation` before persisting:
   ```rust
   // DEFECTIVE IMPLEMENTATION:
   let mut status = UpdateStatus::load(&self.root);
   status.current_generation = Some(prev_gen.clone());
   status.previous_generation = old_current;
   let _ = status.save(&self.root);
   ```
   It never inspected `prev_gen`'s registry or evidence files, leaving `status.sources` and `status.last_summary` frozen with the newer generation's metadata.
2. **Flawed `UpdateStatus::load()` Pointer Prioritization**:
   `UpdateStatus::load()` only read the `current` pointer file if `status.current_generation.is_none()`. If `update_status.json` existed on disk, the JSON content overrode the actual filesystem pointer.
3. **Flawed `bootstrap_from_generation()` Guard**:
   `bootstrap_from_generation()` contained a guard:
   ```rust
   let needs_bootstrap = match self.sources.get(&id) {
       Some(existing) => existing.indicator_count == 0 && existing.source_version.is_empty(),
       None => true,
   };
   ```
   Because `self.sources` had been deserialized from `update_status.json`, `needs_bootstrap` was always `false`, permanently preventing the active generation's immutable metadata from correcting stale status entries.
4. **Conflation of Active State vs. Upstream Observation**:
   `SourceStatus` only had `source_version`, which failed to distinguish between the version active in the compiled RSIDB and the latest upstream version observed during remote queries.

### 1.4 Exact Architectural Fix
The architecture was refactored to establish a **Single Authoritative Active State**:
1. **Filesystem Pointer is Authoritative**:
   `UpdateStatus::load()` now unconditionally resolves `status.current_generation` from the filesystem `current` pointer (with deterministic fallback auto-discovery) and `status.previous_generation` from `previous`.
2. **Immutable Generation Metadata Derivation**:
   `UpdateStatus::load()` unconditionally calls `bootstrap_from_generation()`, which authoritatively reconciles `self.sources` directly from the active generation's `registry.json` and evidence files (`cvd_files` for ClamAV, `acquisitions` for MalwareBazaar).
3. **Explicit State Separation in `SourceStatus`**:
   - `active_version`: The authoritative version compiled into the active generation's RSIDB.
   - `source_version`: Kept identical to `active_version` for full backwards compatibility.
   - `latest_upstream_version`: The remote version observed during checks (preserved across rollbacks and checks).
   - `indicator_count`: Authoritative count directly from the active generation's `registry.json`.
4. **Explicit Rollback Transaction Accounting**:
   `engine.rs:rollback()` now:
   - Atomically updates pointers (`current -> prev_gen`, `previous -> old_current`).
   - Derives the exact initial and final counts from the respective registries.
   - Saves a formal rollback summary adhering to the accounting invariant:
     `final_count = initial_count + 0 - removals`, with `verification_result: "PASS (ROLLBACK)"`.
5. **Self-Healing on Crash or Restart**:
   If `update_status.json` is missing, corrupted, or left with stale data from a crash, `UpdateStatus::load()` immediately self-heals by reading `current` and the active generation's immutable metadata.

## 4. Crash and Interruption Safety Verification

Tested systematically in `test_21_crash_and_interruption_safety_at_transaction_boundaries` across all 7 transaction boundaries:

1. **Interruption after downloading source data**:
   - Injected leftover staging directory `.update-staging-9999-1` containing partial/corrupt data.
   - `load_timed(root, "current")` strictly loaded the verified baseline; partial data remained completely scanner-invisible.
2. **Interruption during generation compilation**:
   - Injected leftover `.phase2d7-unified-crashed.tmp` directory containing a corrupt half-written RSIDB index.
   - `load_timed(root, "current")` strictly loaded the verified baseline without error.
3. **Interruption after compilation & verification but before pointer swap**:
   - Published complete verified generation `gen-verified-unactivated` with 2 indicators.
   - Kept `current` pointer pointing to `gen-verified-base` (1 indicator).
   - Scanner strictly loaded `gen-verified-base` (1 indicator); unactivated generation remained invisible.
4. **Interruption during generation-pointer activation**:
   - Tested pointer replacement: `write_pointer` writes to `.<pointer>.tmp` and executes POSIX atomic `rename()`.
   - Never exposes partial or malformed pointer file.
5. **Interruption between pointer changes and status persistence**:
   - `current` pointer switched to `gen-verified-unactivated`, but `update_status.json` on disk left with old status (`gen-verified-base`).
   - On restart, `UpdateStatus::load()` immediately self-healed to `gen-verified-unactivated` and reconciled source counts (2 indicators).
6. **Interruption during rollback**:
   - Pointers and generations remain atomic; rollback switches `current` and `previous` safely.
7. **Interruption recovery invariant**:
   - **After every interruption, RaxoSentinel either exposes the last verified generation or a completely verified new generation. Never an inconsistent mixture.**

## 7. Remaining Limitations & Blockers

1. **Scheduler Systemd Runtime in Container**:
   As noted in Phase 2D.7B, systemd PID 1 is not running inside this Docker container. Full systemd timer invocation has been statically validated via `systemd-analyze verify`, but runtime systemd validation requires a VM or host environment with an active systemd init.
2. **Third-Party Provider Rate Limits**:
   Live upstream ClamAV DNS queries must maintain rate limits. The current UDP DNS TXT pre-check avoids HTTP bandwidth entirely when upstream releases are unchanged.
3. **Public VPS Deployment**:
   Per strict instructions, no code has been pushed or deployed to the production VPS.
