## 1. Architectural Directive: ONE Unified RSIDB

RaxoSentinel strictly enforces a single canonical runtime intelligence database: **RSIDB (`database.rsidb`)**.

Third-party intelligence feeds—including ClamAV CVD distributions and MalwareBazaar dumps—are treated strictly as upstream intelligence feeds, never as independent runtime databases, secondary engines, or parallel scanner backends. Every imported indicator is validated, normalized, and unified into the native binary format:
- MD5 (16 bytes)
- SHA-1 (20 bytes)
- SHA-256 (32 bytes)
- Monotonically sorted with compact 2-byte prefix indexing and cryptographic provenance records.

## 2. Implemented Subsystems & Modules

### 2.1 Provider Abstraction Framework (`crates/raxosentinel-signatures/src/rsidb/updater/traits.rs`)
- Implemented `IntelligenceProvider` trait providing an extensible, source-independent interface:
  - `check_for_updates(&self, current_state: Option<&ProviderState>) -> Result<UpdateCheckResult, UpdateError>`
  - `acquire(&self, check: &UpdateCheckResult, staging_dir: &Path) -> Result<AcquisitionResult, UpdateError>`
  - `extract_and_normalize(&self, acquisition: &AcquisitionResult) -> Result<ExtractedIntelligence, UpdateError>`
- Implemented `ProviderState`, `UpdateCheckResult`, `AcquisitionResult`, `ExtractedIntelligence`, `NormalizedIndicator`, `RecordKey`, and `UpdateError`.
- Bytecode safety invariant: Zero ClamAV bytecode signatures or executables are evaluated or executed.

### 2.2 ClamAV Intelligence Provider (`.../providers/clamav.rs`)
- CVD version tracking via header inspection (`main.cvd`, `daily.cvd`).
- Hash-based extraction from whole-file `.hdb` and `.hsb` signature sets.
- Exclusion enforcement: parses official `.fp` and `.sfp` false-positive hash files, and `.ign` / `.ign2` ignored signature names to discard revoked signatures.
- Raw evidence preservation: captures CVD header metadata, file lists, and SHA-256 evidence digests.

### 2.3 MalwareBazaar Intelligence Provider (`.../providers/malwarebazaar.rs`)
- API and offline fixture ingestion support.
- Incremental update tracking: detects when recent-record responses are identical and avoids redundant processing.
- Multi-algorithm hash normalization and evidence metadata retention.

### 2.4 Unified Update Engine (`crates/raxosentinel-signatures/src/rsidb/updater/engine.rs`)
Executes the full 9-stage pipeline:
1. **Advisory Lock Acquisition**: Obtains non-blocking `libc::flock(LOCK_EX | LOCK_NB)` on `updater.lock`. Returns `UpdateError::LockContention` if another updater is active.
2. **Provider Update Checks**: Queries all active providers. If no updates are available and `--force` is false, exits cleanly without disk writes.
3. **Acquisition & Upstream Integrity**: Downloads fresh payloads into an isolated staging location. Validates archive integrity.
4. **Extraction & Exclusions**: Normalizes hashes, extracts file sizes, and applies provider exclusion lists.
5. **Multi-Source Claim Reconciliation**:
   - Maintains a claim map: `RecordKey -> BTreeSet<SourceId>`.
   - Indicators claimed by multiple sources record all attributions.
   - If Source A drops a signature but Source B still reports it, the signature remains active.
6. **Mass Deletion Anomaly Review**:
   - Calculates candidate active count vs current active count.
   - If a reduction exceeds `anomaly_threshold_pct` (default: 20%), aborts with `UpdateError::SuspiciousReduction` to prevent corrupted upstream feeds from disarming the scanner.
7. **Isolated Immutable Generation Build**:
   - Compiles a complete native RSIDB (`database.rsidb`) and unified provenance manifests (`associations.json`, `registry.json`, `evidence-*.json`).
8. **Strict Binary Verification**:
   - Validates header magic, binary structure, record sorting, checksums, and representative lookups.
9. **Atomic Pointer Activation & Rollback Preservation**:
   - Publishes staging directory to immutable generation (`phase2d7-unified-<timestamp>`) via `renameat2(RENAME_NOREPLACE)`.
   - Records current generation in `previous` pointer file.
   - Atomically updates `current` pointer file.

### 2.5 Dynamic Generation Resolution (`private_store.rs` & `unified.rs`)
- Added `resolve_generation(root, gen)`:
  - Specifying `--private-generation current` dynamically inspects the active pointer file `current` and transparently loads the active unified generation.
  - Specifying explicit generation names (e.g., `phase2d6-unified`) continues to work identically for backward compatibility.

### 2.6 CLI Subcommands (`crates/raxosentinel-cli/src/main.rs`)
- `raxosentinel db update --check [--root <PATH>]`: Non-mutating status check against upstream feeds.
- `raxosentinel db update --status [--root <PATH>]`: Formatted terminal inspection of current generation, rollback availability, and provider states.
- `raxosentinel db update --apply [--root <PATH>] [--force]`: Executes the complete update engine pipeline.
- `raxosentinel db rollback [--root <PATH>]`: Atomically swings `current` to `previous` generation.

### 2.7 Production Unattended Scheduling & Hardening
- `docs/systemd/raxosentinel-update.service`: Systemd oneshot service with strict Linux sandboxing (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome=read-only`, `PrivateTmp=true`, `RestrictRealtime=true`).
- `docs/systemd/raxosentinel-update.timer`: Jittered timer (`OnCalendar=*-*-* 03:00:00 UTC`, `RandomizedDelaySec=1800`, `Persistent=true`).
- `docs/AUTOMATED_UPDATES.md`: Comprehensive operator and architectural manual.
