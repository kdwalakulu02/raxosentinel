RaxoSentinel Phase 3B.1H — hardening handover

Commit a030e4411f87f124aee3bf29b202e84f945c8d37 on phase-3b.
Status: implemented prototype hardening; complete hostile-worker process-tree containment and full privilege separation remain unmet. Not production ready.

The supervisor copies the already opened regular file, with a running size cap, to an anonymous memfd and seals it against writes, growth, shrinking and further seal changes. The worker receives the sealed descriptor. Tests show the worker sees snapshot bytes after the original is changed, that writes to the snapshot fail, and that the copy enforces the size cap. A concurrent change during copying can yield a mixed snapshot: it is stable after sealing but is not an atomic snapshot of the source. Future mail integration must act on exactly the accepted snapshot. This CLI does not export the snapshot for delivery.

The worker is started in a separate process group. Timeout and parent-detected failures send SIGKILL to the group and reap the direct child. A test starts a real descendant and demonstrates that it is no longer running after timeout. This is not complete containment: descendants can escape the process group/session, and parent cancellation or sudden parent death is not handled reliably. The parent cannot generally reap grandchildren. RLIMIT_AS remains a per-process virtual-address-space limit; no worker-tree memory or process-count limit is enforced. The cgroup v2 hierarchy exposes memory and pids controllers, but /sys/fs/cgroup is not writable for uid 1000 and no delegated subtree is available. No cgroup is created or enforcement claimed. Production requires delegated cgroup v2 with appropriate memory.max, pids.max, cgroup.kill, race-free placement, cleanup on supervisor death, and tests.

The worker environment is cleared and inherited extra descriptors are marked close-on-exec. After existing strict database verification and loading, the worker closes remaining descriptors other than standard streams and applies no_new_privs and a deny-all Landlock ABI 1 filesystem policy before untrusted input parsing; setup failure returns ERROR. An integration test shows the confined worker cannot reopen the original or an unrelated synthetic secret file. This is not full privilege separation: the loader runs first under the caller identity with its filesystem access, and Landlock is not a network, process, syscall, memory, or kernel isolation boundary. Verified database files, trust keys, optional rules and public rollback state must be accessible during loading; public state requires its existing write permissions. Keep signing and authentication credentials and unrelated private data inaccessible to that identity. A dedicated restricted identity and stronger isolation remain deployment blockers.

O_NOFOLLOW rejects the final symlink only; ancestor symlinks remain possible. Future path confinement should use a trusted directory fd and evaluate openat2 RESOLVE_BENEATH or RESOLVE_IN_ROOT, RESOLVE_NO_SYMLINKS and RESOLVE_NO_MAGICLINKS. No current path confinement is claimed. Snapshot copying and synchronous spawn are outside the enforceable worker deadline.

Tests: cargo fmt --all -- --check, cargo clippy --workspace --all-targets -- -D warnings, and cargo test --workspace passed; one pre-existing scale benchmark is ignored. Added snapshot seal/limit and concurrent modification tests, descendant termination and filesystem denial tests. Existing strict private and signed-public verification tests pass. Debug builds include test fault hooks and are not for production.

Release benchmark: Linux 6.8.0-1064-azure x86_64, warm cache, synthetic repeated-byte inputs, built-in signatures, same defaults for both paths, five runs each; /proc VmHWM sampled every 1 ms (may miss short peaks), sizes decimal bytes. Median direct vs supervised: empty 2.69 vs 5.23 ms; 1 MB 7.88 vs 15.29 ms; 10 MB 54.17 vs 59.61 ms; 50 MB 242.68 vs 276.16 ms. For 50 MB, sampled direct peak RSS 53,664 KiB, supervisor peak 3,828 KiB and worker peak 53,592 KiB. The memfd uses kernel memory not captured by those process RSS figures. These are local synthetic measurements, not resource guarantees.

Overhead investigation: the old worker preliminary type detector inspected the complete input, including UTF-8/control-character checks, whereas the direct path used only its first 8 KiB; the subsequent shared object scan still performs its normal inspection. The worker preliminary check now uses the same 8 KiB as the direct path. In a preceding release run before this change, 50 MB supervised median was 321.71 ms; afterward it was 276.16 ms, versus 228.63 and 242.68 ms direct in those runs. This is consistent with extra work being a contributor but is not a controlled attribution of the previous debug result. Snapshot copying, startup and scheduling also differ; no precise breakdown was measured.
