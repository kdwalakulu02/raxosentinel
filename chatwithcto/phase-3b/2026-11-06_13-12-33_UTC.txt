RaxoSentinel Phase 3B continuation — CTO report

STATUS: INCOMPLETE. Do not deploy or treat this as a release candidate. Source changes remain uncommitted on phase-3b. No push or release publication. Ubuntu 24.04 build and verified private-store scan remain outstanding, as does complete safe handling of all embedded archive variants.

ROOT CAUSE AND CURRENT CORRECTION
The original scanner classified ZIP only by a ZIP header at offset zero or ZIP metadata. A PDF-prefixed ZIP was scanned as raw PDF. Stored EICAR remained visible in raw bytes; deflated EICAR required decompression and was missed. The experimental dispatch now finds a local ZIP header at any offset and lets ZipArchive validate structure before extracting. Existing depth, extraction budget and timeout controls remain in the extraction path. Invalid or truncated candidates return UNSCANNED. Multiple ZIP end-record markers yield UNSCANNED unless a detection takes precedence, because ZipArchive selects one directory and cannot establish that all archives were inspected.

LIMITATIONS: This is not a complete solution for all requested polyglots. Multiple archives are not all extracted; an earlier compressed payload can be missed, though multiple visible end markers prevent a CLEAN verdict. End-record and header byte searches may create conservative false UNSCANNED results. Embedded unsupported formats and truncated archives lacking a recognizable header are not comprehensively discovered. Archive-looking data may occur inside other file content. Do not claim complete inspection. Further design and security regression tests are required before release.
