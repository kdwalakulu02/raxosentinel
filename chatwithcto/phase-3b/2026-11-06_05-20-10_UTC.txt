## 3. Changes made

- Restricted the worker fault-injection gates to debug builds in the scanner, coordinator and supervised worker code. The earlier handover's release opt-in behavior is superseded by this change.
- Added `client --json-envelope` to expose the existing coordinator response, including verdict, error and database generation, while retaining the existing `--json` output.
- Added `integration/shadow-scan.js`: a standalone staging harness that copies an attachment to a private temporary location, runs ClamAV and the coordinator client with bounded subprocess deadlines, and emits scanner records without attachment content. It has not been run because Node.js is absent. It does not write PostgreSQL or deliver email; the actual mail integration must ensure both engines receive the same immutable content and preserve ClamAV's existing blocking decision.
- Added `integration/raxosentinel.service`, `integration/coordinator.env`, and `integration/README.md` as unvalidated deployment templates and staging guidance. The service uses an internal Unix socket and configurable worker settings. Its same-user socket access requirement must be reconciled with the real mail deployment.
- Private intelligence was kept outside the Git repository. Existing updater functionality was not changed.
