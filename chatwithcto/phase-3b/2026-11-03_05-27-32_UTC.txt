RaxoSentinel Phase 3B.1 — supervised worker handover

Implementation commit: be3618e7c354dfac6af917c9e042a2822c3c7e20 on phase-3b.

Run: raxosentinel scan FILE --supervised --json [--worker-timeout-ms N] [--worker-memory BYTES]. The parent opens the target once with O_NOFOLLOW and O_NONBLOCK, checks the opened descriptor is a regular file and within the file-size cap, then passes it as worker stdin. The worker checks the descriptor again and uses the existing byte scanner and strict private or signed-public loader. A scan with no external database uses built-in signatures. Supervised mode rejects legacy DB/store options. Responses are capped at 2 MiB and parsed as ScanReport with matching exit status; command arguments are capped at 64 KiB. Timeout kills and reaps the direct child, and worker failures return ERROR. Original direct CLI remains available.

Security boundaries: Linux RLIMIT_AS is a virtual address-space limit, not an RSS cap. The parent deadline is independent of cooperative scanner checks, but the synchronous OS process-creation step itself cannot be interrupted by that deadline. The worker is not sandboxed or privilege-separated: it retains the caller's filesystem access, can read unrelated material and can spawn descendants. Only the direct worker is killed/reaped. Contents may be modified in place during scanning; ancestor symlinks remain possible. Debug builds contain environment-controlled fault injection and are not for production. CLEAN is not a guarantee of safety. See crates/raxosentinel-cli/SUPERVISED.md.

Verification: cargo fmt --all -- --check, cargo clippy --workspace --all-targets -- -D warnings, and cargo test --workspace passed. One pre-existing scale benchmark remains ignored. New integration tests exercise the real worker for clean, synthetic detection, ZIP detection, descriptor validation, final-component symlink rejection, path replacement after open, private verification failure, public signed release, low address-space limit, injected crash, timeout, malformed/oversized output, direct-child reaping and subsequent recovery. Existing CLI tests continue to pass. Fault injection is compiled only into debug builds.

Measurements: local Linux 6.8.0-1064-azure x86_64, debug build, built-in signatures only, harmless repeated-byte files, warm filesystem cache, five runs per case. Median elapsed times: empty direct 7.95 ms, supervised 10.46 ms (2.51 ms difference, approximate startup overhead including protocol and supervision); 1,000,000 bytes direct 94.57 ms, supervised 115.92 ms (+21.35 ms); 10,000,000 bytes direct 889.74 ms, supervised 1073.67 ms (+183.93 ms). Sampled /proc VmHWM for supervised 10 MB: parent 7,884 KiB, worker 18,816 KiB. The 1 ms sampling can miss short-lived peaks and is not an OS guarantee. An injected hang with a 100 ms deadline returned in median 106.23 ms; a subsequent supervised 10 MB scan took 1063.98 ms. These synthetic measurements do not establish production throughput, cold-cache performance or memory guarantees.
